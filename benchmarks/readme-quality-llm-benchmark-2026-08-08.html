06Methodology & provenance

  • Task shape. One "Add README" quick-fix workflow task per (model, effort), all against a byte-identical copy of the same Redaction System source. Each task's headline model drove every LLM step via ignore_saved_step_clis, so triage, estimate, app-boot, implement and validate are all attributable to that model.
  • Which runs count. Inclusion is "produced a README", not "task status = completed" — three published rows (1a99485a, 8500e207, 8d2987c9) come from tasks later marked cancelled that had already written and committed their README. All nine new runs completed normally and committed. One duplicate is excluded: a second Muse-low task (26cf4a4c) re-ran the same repo an hour after 9de5cb55, finished in five minutes and committed nothing, so it produced no artifact to score.
  • Model identity is read from the system/init event of each run's stream log, not from the task title or the cli_providers.model column. The five new Anthropic runs echo claude-opus-5; the four Meta runs echo muse-spark-1.2 — which matters because the Muse Spark 1.2 xHigh provider row has an empty model column and inherits the adapter default.
  • Validity. For every run the newest 07-phase-2-implement invocation's provider is compared against the task's provider; a mismatch would mean the README was written by a different model than the row claims. All 55 match.
  • Scoring rubric (unchanged): accuracy = are the claims true of this source tree, completeness = does it cover stack, architecture, domain model, install/config, security posture and credits, clarity = can a newcomer act on it. Composite = accuracy×5 + completeness×3 + clarity×2. Hallucinations counts distinct fabricated facts — invented tables, files, mechanisms, or harness values presented as project reality.
  • Calibration note on clarity. Across all 55 runs clarity has only ever been scored 8 or 9; no README has earned a 10. That makes 98 the effective maximum of this rubric, which is why the top of the table is a three-way tie rather than a ranking. Two of this edition's runs are pinned there on the same evidence standard as the incumbent: zero fabricated facts and full coverage including security posture.
  • Source verification. Every claim quoted as a strength or a defect in the nine new rows was checked against the repository. Confirmed this edition: the calypso/rs1_final release notes against RS_CODENAME='atlantis'/RS_VERSION='beta2' at installer/init.php:139-140; FCKeditor 2.5 Beta build 16848 (dashboard/editor/js/fckeditorcode_gecko.js) — the first time any run has given the bundled editor's real version; the 23-table schema; actions/ being exactly 26 admin + 4 public files; m_main IS NULL as the show-under-every-tab rule (thememanager.php:612); ranks.nazov and admins.prezyvka/heslopwd; and the search stub in themes/alternative/index.php with no MATCH … AGAINST anywhere in the tree.
  • Defects were confirmed the same way, by opening the file: there is no .htaccess in the repository (muse-low asserts alias routing through one, twice); there is no aliases table, no sessions table and no kwords table (muse-xhigh names all three); menus.parent is the self-referencing menu parent, not the tab id (muse-high); the schema creates 23 tables, not ~25 (muse-high); and no customer/seller rank seeds exist.
  • Harness bleed is scored as hallucination when the README presents benchmark infrastructure as project fact. Three Muse runs do: muse-medium ships a "### DDEV (recommended)" install section, muse-high puts "do not call ddev inside the sandbox" in a fenced setup block, and muse-xhigh carries a "No DDEV in sandbox" bullet. All five Opus 5 runs are clean of DDEV and sandbox text; opus5-xhigh carries only MariaDB 10.11, attributed to AGENTS.md, which is scored as an accuracy deduction rather than a fabrication.
  • Cost figures come from cli_invocations grouped by step, summed across retries including superseded rows. The query was validated before use by reproducing the published implement-token values exactly for 44 of the 44 checkable prior runs (Sonnet 4.6 low 7,200 / medium 8,546 / high 10,258 and so on); the remaining two rows are the metering-failure run and one without a published data point.
  • Raw input/total tokens are excluded — providers cache differently and the Claude-family runs are ~98% cache reads, so only output tokens and active duration compare across models.
