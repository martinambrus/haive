### Regenerating

The data arrays are inlined in each HTML file. Source data comes from the Haive DB (`tasks`, `task_steps`, `cli_invocations`), each repo's on-disk `.claude/` artifacts, and the separate `haive_kb_global` DB. Quality scores come from a structured, source-verified multi-agent audit. Edit the relevant `DATA` array to refresh.

The published composite is `KB 25% + Skills 25% + Detection 20% + Agents 15% + Global KB 15%`.

Cost is reported two ways from 8 August onward. **Billed** sums every `cli_invocations` row including superseded retries, so a rerun pays for failed attempts instead of hiding them - the rule all earlier editions used. **Live** restricts the sum to `superseded_at IS NULL`. Keep both: billed is the honest number when retries are the model's fault, live is the honest number when they are the harness's. Read the retry reasons (`cli_invocations.error_message`) before deciding which a given round needs - "orphaned by a worker restart" and rows that already exited 0 are not model cost.

Citation figures in these reports are a **structural** check only: the cited file exists and the cited line is within it. That cannot detect a citation naming a real file and an in-range line belonging to a different function, which is a real observed failure mode (`muse-high`, 8 August), nor a wrong identifier that never appears in a citation at all - which is how `opus46-high`'s misapplied `rs2_` table prefix (20 August) passes a 0/115 link score and 99.86% citation resolution. An anchored symbol-to-span precision metric was built for the 8 August edition and discarded as unreliable - lines naming two symbols cross-attribute their citations, and it produced false misses. Treat published citation percentages as a floor on accuracy, never a ceiling; anything called a wrong citation in these reports was confirmed by opening the file.
