# Per-call agent isolation

Per-call agent isolation (default on, `CONFIG_KEYS.AGENT_ISOLATION_ENABLED`): an invocation that has no use for the repository's agent definitions is given EMPTY ones, and the persona it does need is pasted into its prompt instead of pointed at. Every CLI lists its agent directory eagerly — names and descriptions, on every call — so for a reviewer or a miner that listing is pure context cost, and the claude binary's own 8,000-char budget (bundled skills charged first) left 1 of 18 repo skills described. `agentIsolationApplies` (`orchestrator/dispatcher.ts`) is the whole rule, pure, and all seven must hold: the switch is on, `input.kind === 'prompt'` (the sub-agent kinds rebuild each sub-step's spec worker-side), no `file_write` (a tmpfs mask is WRITABLE, so an edit to a masked agent file would vanish with the container), no `subagents` (a dispatch that may spawn native sub-agents keeps the catalog it spawns from), the step declared no `agentPool: '*'` (`07_7-secret-sweep` does, because agent definitions are committed files and its whole contract is sweeping the committed tree), nothing names an agent directory or a file inside one — the prompt with Haive's own marker blocks stripped, every persona body it carries scanned VERBATIM, and the selected provider's instruction chain (`adapter.rulesFile`, following `@` imports only in `import` mode) — and the EXTERNAL text the dispatcher appends after the decision names none either. That last condition exists because `adaptPrompt` splices the MCP surface and the global-KB digest in AFTER the rule returns, and both carry strings Haive did not write: a repository's own `mcpServers` keys, taken verbatim from its `.claude/mcp_settings.json`, and author-written KB titles. Without it a repository could name a server `.claude/agents/foo` and reach an isolated invocation's final prompt with a path the mask then hid. It scans ALL user server keys rather than the ones a given run renders — `reachableUserServerNames` needs the emitted-server set, which depends on render options a pure rule does not have, and shadowing is run-time state, so a name shadowed today renders tomorrow and isolation keyed on it would flicker between runs of one repository. `withAppReach` is the third post-decision append and needs NO scan: it interpolates `reach.url` alone, which is ddev's `primary_url` (scheme://host[:port], no path component), and a hostname cannot contain a slash. The provider's agent rules block ([Agent rules](agent-rules.md)) is the fourth and last, and it IS scanned: its text is a person's to edit, so the final decision in `buildCliSidePlan` takes it as external text too. The async pre-check runs before a provider is known, so it scans no rules and can only ever be the more permissive of the two. `promptNamesAgentPath` (`@haive/shared`) matches on whole segments from the root, so `.claude/agents/x.md` counts while `docs/.claude/agents/x.md`, `.claude` alone and the `-legacy` quarantine sibling do not. The two scans fail in OPPOSITE directions on purpose: the instruction scan fails OPEN (a file it cannot read, or a chain past 5 imports or 1 MiB, ends isolation, because a truncated scan must never hide a referenced file), while the persona reader fails CLOSED (a secret-mask policy it cannot evaluate pastes nothing, since a body already in a prompt cannot be retracted). An `@` import is resolved where the CLI resolves it, in the sandbox: against the importing file's directory under `/haive/workdir`, followed while it lands inside the mount, and counted when its own path names an agent file (`@docs/../.claude/agents/x.md`). One that lands outside is not followed, since nothing there is the repository's; a worktree run mounts only the worktree, so its imports cannot reach the repository root. Bodies are read by FILENAME from that provider's own `projectAgentsDir`, never by the frontmatter `name` `loadAgentPersonas` keys on — the two can differ, and a name lookup would silently drop the customisation that outranks the inline persona — never follow a repository-controlled link (`readFileNoFollow` refuses a link in any component and verifies the descriptor it opened), and share one 64 KiB budget counted from each opened file's own `fstat` size, where a body that would exceed the remainder is never pasted and never truncated (a cut definition reads as a complete one) and records an `agent_persona.oversized` task event. Exec never reads the switch: the decision rides `CliCommandSpec.maskAgentDefinitions`, which is what keeps one invocation's prompt and its mounts on the same side of a flip, and `resolveAgentDefinitionMasks` (`queues/cli-exec/agent-definition-mask.ts`) then mounts a read-only empty tmpfs over every catalog agent directory that EXISTS — masking an absent one makes Docker materialise a root-owned stub that outlives the container, and on a read-only local-path mount it cannot be created at all. Unlike secret masking this FAILS OPEN throughout: a stat that throws masks nothing and logs, because it is a context control and the persona is already in the prompt. Secret and `#ddev-generated` file masks whose target falls under a masked directory are dropped (Docker cannot make a mountpoint inside a read-only tmpfs), and a stub Docker left behind is removed in a `finally` only when it did not exist before the run, is owned by the run's uid, and is still empty.
